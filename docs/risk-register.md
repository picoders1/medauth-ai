# Risk Register

Failure modes with evidence. An item leaves this list only with the artefact that resolved it.

**Status:** Phases 0–19 delivered. Likelihood and impact began as pre-implementation
judgements and are revised against measurement in the phase shown. The header this replaces still
said "planning phase … no code exists", which had been false for eighteen phases — corrected by the
final closure audit, which also explains why the individual R-01…R-33 statuses were **not**
re-adjudicated in the same pass (`docs/engineering/final-closure-audit.md` §5).

| | |
|---|---|
| **Open** | identified, not yet mitigated — **or** a standing risk class a control reduces but cannot retire (automation bias does not become `Resolved` because a UI renders evidence first). The register has always used the word both ways; saying so is the closure audit's correction |
| **Mitigated** | a control exists and a test asserts it |
| **Accepted** | will not be fixed; the reason is recorded |
| **Resolved** | an artefact demonstrates it no longer applies |

## Security risk

| ID | Risk | Impact | Mitigation | Status | Phase |
|---|---|---|---|---|---|
| **R-14** | **Indirect prompt injection via retrieved policy text, with the firewall providing little protection** (its measured indirect recall is 0.1423, planted-content recall 0.0938). | Critical | Five structural layers in MEDAUTH (fenced delivery, closed schemas, span-verified quotes, code-computed decision, per-criterion isolation). **Containment is unmeasured until Phase 8** and no containment claim is made before then. | Open | 4, 8 |
| **R-15** | Corpus poisoning — stored policy text altered or a fabricated policy inserted. | Critical | Content hashes at document and chunk level; ingest only from registered sources; historical citations re-validatable. | Open | 1, 8 |
| **R-16** | Audit tampering — selective deletion to hide a recommendation. | Critical | Append-only grants; retention deletes by `created_at` and nothing else, asserted against the compiled SQL. **Schema delivered (parallel track).** `audit_events` and `human_review_events` exist and are append-only **by trigger**, with grants as defence in depth. The grants alone were not enough and finding that out is the finding: `REVOKE UPDATE, DELETE` applied cleanly, read correctly in `information_schema`, and was **inert** - PostgreSQL does not enforce grants against a table's owner, and the application user owns its schema. A row-level trigger then refused UPDATE and DELETE while **TRUNCATE went straight through**, because a per-row trigger never fires on a statement that removes rows without visiting them. Both defects were found by executing the statements, not by reading. Each table now carries a row-level and a statement-level trigger; `purge_audit_before(timestamptz)` takes one parameter and has one predicate, and restores the guard on both the success and failure paths. 12 schema tests and 7 integration tests. **Residual, stated in the architecture doc:** a superuser can disable a trigger, so the earned claim is *no application code path can mutate the trail*, not *the trail is immutable*. **Nothing writes to it yet** - the runtime is not wired through it. | **Mitigated (schema); the runtime is not yet wired** | 7 |
| **R-17** | Clinical text leaks into logs, spans or audit payloads. | High | Redaction at the sink; audit payloads carry ids and spans; schema-level assertion that no column holds a prompt or completion. **The schema now exists to assert over (parallel track).** `audit_events` has no `Text` column and every `String` is bounded at 64 characters, asserted by walking the metadata. The submitted payload is not stored - `cases.input_sha256` records its digest instead. The only unbounded columns in the audit module are a reviewer's own `rationale` and `reviewer_qualification`, and a test asserts they are the only two. | **Mitigated (schema); the runtime is not yet wired** | 7, 8 |
| **R-18** | The provider credential leaks. | High | MEDAUTH never holds it — the firewall does. `gitleaks` over full history in CI. **The key was shared in a planning conversation and should be rotated.** | Open | 0 |
| **R-19** | Firewall false positives block legitimate clinical notes. | Medium | Measured from Phase 0; `403` is never retried; the case routes to `HUMAN_REVIEW`. A material rate is a finding recorded in both repositories. | Open | 0 |
